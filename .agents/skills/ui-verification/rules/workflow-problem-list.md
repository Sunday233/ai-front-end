## UI 问题清单文档结构

### 文档路径

```
docs/样式还原/<名称>-UI问题清单.md
```

### 文档结构建议

```markdown
# <名称> - UI 问题清单

> **参照文档**：`docs/样式还原/<名称>-UI分析清单.md`  
> **设计稿**：`docs/设计稿/<路径>/<文件名>.pen`、Figma 链接或 Stitch 链接  
> **设计源定位**：页面/画板/Frame/节点 ID（如有）  
> **实现页与视口**：URL、viewport
> **浏览器工具**：Codex in-app Browser (`iab`) / Browser / Playwright MCP / 其它；若未用 Browser 完成验收，写明失败阶段和降级依据
> **验收证据**：实现页截图/快照、设计稿截图/节点信息或结构化清单
> **创建/更新日期**：YYYY-MM-DD

## 一、按区域列问题（区域按从上到下、从左到右顺序排列）

### 区域 A
| 编号 | 问题描述 | 类型 | 当前实现 | 设计稿要求 | 优先级 |
|------|----------|------|----------|------------|--------|
| A1   | ...      | ...  | ...      | ...        | P0/P1/P2 |

### 关系型区域核对（如表格、左右映射、字段-属性映射）
| 源字段/行 | 当前实现映射 | 设计稿要求 | 状态/操作差异 | 优先级 |
|-----------|--------------|------------|----------------|--------|
| ...       | ...          | ...        | ...            | P0/P1/P2 |

## 二、问题统计与修复顺序

| 优先级 | 数量 | 说明 |
|--------|------|------|
| P0（布局/层级/内容） | n | 先修，不得遗漏 |
| P1 | n | 次之 |
| P2 | n | 可后续 |

建议修复顺序：P0 → P1 → P2；同优先级内按**从上到下、从左到右、从外到里**。

## 三、验收结论（随修复更新）

- [ ] **P0（布局、层级、文字、图片）** 全部修复，且验收时已按从上到下、从左到右、从外到里逐项检查无遗漏
- [ ] P1 全部修复
- [ ] P2 已记录/部分修复
- [ ] 已使用 Codex in-app Browser / Browser 或 Playwright 进行实际页面与设计稿/分析清单比对
- [ ] 若未使用 Browser 完成验收，已记录失败阶段、替代工具、视口和证据
- [ ] 表格/列表/左右映射/字段属性映射已逐行核对
- [ ] 修复后已再次使用 Browser 或 Playwright 回归验证
- [ ] 还原度自评：___%
```

### 问题描述要求

- **问题描述**：简短、可操作（如「欢迎语区域整体水平居中」）
- **当前实现**：现状（如 `align-items: center`）
- **设计稿/分析清单要求**：明确要求（如「左对齐 flex-start」）
- **优先级**：便于排期与迭代
