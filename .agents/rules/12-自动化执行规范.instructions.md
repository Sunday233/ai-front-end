# PRD + UI 自动执行规范

## 触发条件

当用户输入或引用 `docs/prd/*.md`，并表达创建提案、实现页面/UI、根据设计稿还原、自动实现或验收等意图时，必须进入本规范。

## 强制执行顺序

1. **PRD 读取与设计源识别**
   - 读取目标 `docs/prd/*.md`。
   - 识别 PRD 中的设计源：`docs/ui` 截图、`.pen` 文件、Figma 链接、Stitch 链接。
   - 若同一 PRD 同时声明多类设计源，按 PRD 中的 `primary_design_source` 选择主设计源，其他源作为补充。

2. **设计稿分析**
   - 使用 `.agents/skills/design-analysis/SKILL.md`。
   - 根据设计源选择工具：截图使用截图模式，`.pen` 使用 Pencil MCP，Figma 链接使用 Figma MCP，Stitch 链接使用 Stitch MCP。
   - 产出 `docs/样式还原/<prd_slug>-UI分析清单.md`。

3. **组件拆分规划**
   - 使用 `.agents/skills/component-planning/SKILL.md`。
   - 基于 PRD、UI 分析清单、设计稿/截图与现有代码，产出 `docs/组件拆分/<prd_slug>-组件拆分清单.md`。
   - 清单必须区分页面级组件、公共组件、现有可复用项与候选复用项。
   - 页面级组件默认放在 `src/views/<page>/components/`；公共组件只有第二处真实使用后才抽到 `src/components/`。

4. **OpenSpec 提案**
   - 使用 `.agents/skills/create-proposal/SKILL.md`。
   - 产出 `openspec/changes/<change-id>/proposal.md`、`tasks.md`、`specs/<capability>/spec.md`，必要时产出 `design.md`。
   - `tasks.md` 必须写明依据 UI 分析清单实现，并在实现后执行 UI 验收。
   - UI 类 change 的 `design.md` 必须引用 `docs/组件拆分/<prd_slug>-组件拆分清单.md`，`tasks.md` 必须写明按组件拆分清单实施。
   - 执行 `openspec validate <change-id> --strict` 前，必须完成组件拆分前置检查；通过后进入实施，命中高风险操作时先人工确认。

5. **页面/UI 开发**
   - UI 类 change 在 apply 前必须检查组件拆分清单、`design.md` 引用与 `tasks.md` 约束；缺任一项时暂停。
   - 按 `tasks.md` 顺序实施。
   - 开发前读取相关 Rules：项目结构、组件、路由、样式、通用约束、测试规范。
   - 开发中使用相关 Skills：`create-route`、`create-component`、`theme-variables`，涉及接口时使用 `create-api`。
   - 依据 UI 分析清单还原布局、文字、图片、层级与样式。

6. **UI 验收**
   - 使用 `.agents/skills/ui-verification/SKILL.md`。
   - 在 Codex 或 Cursor 中优先用 `@Browser` 打开实现页；不可用时用 Playwright MCP。
   - 与设计稿或 UI 分析清单比对，按 P0/P1/P2 产出 `docs/样式还原/<prd_slug>-UI问题清单.md`。
   - 修复后必须再次使用 Browser 或 Playwright 验证。

## UI 类 Change 判定与前置检查

命中任一条件即视为 UI 类 change：

- PRD、proposal、design 或 tasks 中出现 `docs/样式还原`、UI 分析清单、页面、组件、设计稿、UI 还原、Figma、Stitch、Pencil、`docs/ui`。
- 影响代码包含 `src/views`、`src/components`、`src/layout`。
- 交付物包含页面实现、功能组件、样式还原或 UI 验收。

UI 类 change 在 validate 与 apply 前必须检查：

- `docs/组件拆分/<prd_slug>-组件拆分清单.md` 存在。
- `openspec/changes/<change-id>/design.md` 引用了该清单路径。
- `openspec/changes/<change-id>/tasks.md` 包含“按组件拆分清单实施”的任务。

缺任一项时必须暂停，先补齐组件拆分清单或 OpenSpec 资产。

## PRD 设计源识别规则

PRD 应优先使用以下字段：

| 字段 | 用途 |
|------|------|
| `primary_design_source` | 主设计源类型：`docs-ui` / `pen` / `figma` / `stitch` |
| `required_ui_assets` | `docs/ui` 下必需截图 |
| `design_pen_files` | `.pen` 设计稿路径 |
| `figma_links` | Figma 设计链接 |
| `stitch_links` | Stitch 设计链接 |
| `ui_analysis_output` | UI 分析清单目标路径 |
| `ui_verification_output` | UI 问题清单目标路径 |
| `component_plan_output` | 组件拆分清单目标路径 |

若字段缺失：

- `docs/ui/<prd_slug>*.(png|jpg|jpeg|webp)` 存在时，默认 `primary_design_source=docs-ui`。
- PRD 正文包含 `.pen` 路径时，识别为 Pencil 设计源。
- PRD 正文包含 `figma.com` 链接时，识别为 Figma 设计源。
- PRD 正文包含 `stitch` 链接或明确写有 Stitch 设计稿时，识别为 Stitch 设计源。

## 高风险人工确认

以下情况不得自动继续实施：

- 删除或重构大范围既有业务代码。
- 修改认证、权限、支付、数据迁移、安全策略等高风险能力。
- PRD 与设计稿存在 P0 冲突且无法自行判断优先级。
- 缺少关键设计源且 PRD 未提供可执行 UI 描述。
