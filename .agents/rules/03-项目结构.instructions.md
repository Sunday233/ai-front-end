# 项目结构（NON-NEGOTIABLE）

## 目录结构

```text
src/
├── assets/        # 字体、图标、静态图片等资源
├── components/    # 可复用 UI 组件
├── composables/   # 自定义 Composables（Composition API）
├── constants/     # 业务常量、枚举
├── layout/        # 全局布局组件（Header、Sidebar、Footer 等）
├── router/        # Vue Router 配置
├── services/      # API 请求封装（client + 每页 service）
├── stores/        # Pinia stores，按业务拆分
├── styles/        # 全局样式（仅允许 reset/variables/index）
├── types/         # 接口、模型、DTO 类型声明
├── views/         # 场景路由页面
├── utils/         # 通用工具函数
└── 根级文件        # App.vue、main.ts 等入口文件
```

## 结构约束（禁止在 src 下新建非标准目录）

| 类型 | 目录 | 规范 |
|------|------|------|
| 常量 | `src/constants/` | 按模块划分，所有模块导出到 `index.ts` |
| 状态 | `src/stores/` | 按业务模块划分，使用 Pinia，暴露 `useXxxStore` |
| 工具 | `src/utils/` | 按功能模块划分，所有模块导出到 `index.ts` |
| API 请求 | `src/services/` | `client.ts` 统一 axios 封装，每个页面一个 `src/services/<page-slug>.ts`，每页 mock 独立放在 `src/services/<page-slug>.mock.ts` |
| 接口类型 | `src/types/` | 每个页面目录含 `model.ts` 和 `api.ts` |
| 组件 | `src/components/` | 每个组件独立目录，导出到 `index.ts` |
| 页面 | `src/views/` | 每个页面含 `index.vue`、可选 `components/`，页面样式默认写在 SFC 的 `<style scoped lang="scss">` 中 |
| 路由 | `src/router/` | 路由配置文件 |
| 全局样式 | `src/styles/` | 仅允许 `reset.scss`、`variables.scss`、`index.scss` |

## 页面目录内的组件放置规则

页面专用组件放在 `src/views/<view-name>/components/` 目录：

```text
src/views/<view-name>/
  ├─ components/           # 仅供当前页面使用的子组件
  │   └─ xxx/
  │       └─ index.vue
  ├─ index.vue             # 页面主文件
  └─ index.module.scss     # 可选：仅在页面样式需要复用时使用
```

**判断标准**：

- 通用组件：多处复用、业务无关 → `src/components/`
- 页面级组件：仅单页使用 → 页面目录下的 `components/`

**约束**：`src/components/` 只存放通用组件，禁止将仅单页使用的组件放入。

## 样式边界（全局 vs 局部）

- 页面/组件默认使用 `<style scoped lang="scss">`。
- 仅在样式需要跨组件复用时，才使用 `.module.scss`。
- 全局样式仅允许放在 `src/styles/reset.scss`、`src/styles/variables.scss`、`src/styles/index.scss`。

## Mock 数据策略

当后端接口未完成时：

### 目录结构

```text
src/
  ├─ services/
  │   ├─ client.ts         # axios 实例、Token、错误处理、响应解包
  │   ├─ mock.ts           # mock adapter/handler 注册入口，仅负责统一注册
  │   ├─ <page-slug>.mock.ts # 页面 mock handler / mock 数据
  │   └─ <page-slug>.ts    # 页面 API 请求函数，mock/real 调用签名一致
  └─ types/
      └─ <page-slug>/
          ├─ model.ts
          └─ api.ts
```

### 原则

1. 接口文件：创建 `src/services/<page-slug>.ts`，始终通过 `httpClient` 发起请求
2. 请求封装：`src/services/client.ts` 统一创建 axios 实例，配置 Token 拦截器、错误处理与响应解包
3. mock 入口：`src/services/mock.ts` 或同等请求层 handler 只负责统一注册；页面 mock handler 与 mock 数据放在 `src/services/<page-slug>.mock.ts`
4. 类型定义：使用 `src/types/<page-slug>/model.ts` 与 `src/types/<page-slug>/api.ts`
5. 文档汇总：新增或修改接口后更新 `docs/api/接口汇总.md`
6. 状态管理：不创建独立 Pinia store，必要时使用组件内响应式状态
7. 优先级：UI 还原度优先于功能完整

### 禁止

- 禁止创建复杂的 mock 数据结构
- 禁止创建独立的 store（接口未完成时）
- 禁止预留过多扩展字段
- 禁止在页面、组件、store 中直接写 mock 数据分支
- 禁止在页面 service 中用 `if (isMock)` 绕过 `httpClient`
- 禁止把多个页面的 mock handler / mock 数据集中堆在同一个业务 ts 文件中
- 禁止让 `src/services/mock.ts` 承载具体页面 mock 逻辑；它只能注册各页面 mock handler
