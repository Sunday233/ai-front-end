# 组件拆分清单目录说明

## 目录用途

本目录用于沉淀 UI 类需求在 OpenSpec apply 前的页面组件拆分指导。

组件拆分清单用于说明：

- 哪些组件属于当前页面专用组件。
- 哪些组件可以复用已有公共组件或布局。
- 哪些组件具备复用潜力但暂不抽公共组件。
- apply 阶段必须按哪些边界创建、复用或调整组件。

## 命名规范

```text
docs/组件拆分/<prd_slug>-组件拆分清单.md
```

示例：

- `docs/组件拆分/workbench-组件拆分清单.md`
- `docs/组件拆分/object-type-list-组件拆分清单.md`
- `docs/组件拆分/object-type-create-组件拆分清单.md`

## 使用规则

1. UI 类 OpenSpec change 在 apply 前必须有组件拆分清单。
2. OpenSpec change 的 `design.md` 必须引用对应清单路径。
3. `tasks.md` 必须包含“按组件拆分清单实施”的任务。
4. 公共组件只有第二处真实使用后才抽到 `src/components/`。
5. 页面级组件默认放在 `src/views/<page>/components/`。

````markdown
```text

```

## Apply 约束

- 实施必须优先复用“现有可复用项”。
- 页面级组件默认放在 `src/views/<page>/components/`。
- 公共组件只有第二处真实使用后才抽到 `src/components/`。
- 若实现偏离本清单，必须先更新本清单或在 tasks 中记录原因。
````
